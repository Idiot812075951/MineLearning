# 机械单位构筑玩法——功能 Review

> 评审日期：2026-09-26。本文保存自本次对话中的文档一，未新增设计结论。
>
> 评审依据是[玩法草案](../肉鸽系统.md)、当前工作区 C++ 实现及相关项目文档。已通过 Unreal MCP 成功查询到本项目 Combat 资产；评审期间没有运行编译、测试或 PIE。文中区分代码现状和设计建议，不把方案当成已验证实现。
>
> 配套文档：[程序框架 Review](Roguelite_Architecture_Review.md)。

## 1．总体判断

这套方向合理，而且与现有采矿、生产、运输、幻化有结合空间。

真正有价值的是：玩家需要在“扩大生产、培养单位、提升个人操作能力、准备终局挑战”之间分配资源。Buff、天赋、召唤师和合体应该服务于这些决策。

但草案目前有三个明显问题：

- **成长入口很多，独立决策未必足够。** 同一种能力可能经过天赋解锁、召唤师解锁、局内前置、合体、觉醒五道门槛。
- **强调组合，没有充分定义代价。** 如果生产没有压力、合体必然更强、觉醒必然覆盖原技能，玩家最终只是等待最优路线完成。
- **当前游戏循环与目标循环存在差距。** 现有实现是不限时生产、付费挑战 Boss、失败保留经营成果再挑战，尚未形成有明确结束边界的 Roguelite 单局。

建议保留四类系统，但先确定它们分别承担什么责任。

| 系统 | 应负责的决定 | 不宜重复承担 |
|---|---|---|
| 局外天赋 | 以后能接触哪些内容、选择哪些开局方向 | 每局具体拿到什么强化 |
| 召唤师 | 本局采用什么优势与限制 | 再复制一棵永久数值树 |
| 局内强化 | 本局如何组合和专精 | 负责所有生产、解锁、经济行为 |
| 单位合体 | 牺牲哪些现有单位，换取什么新能力 | 无条件替代全部低阶单位 |

**评审结论：建议推进，但不建议同时铺开四个完整系统。先验证一个能玩出差异的局内构筑闭环。**

## 2．局内 Buff：四类内容成立，但不应该是四套系统

草案中的分类可以保留：

| 类别 | 玩家感受 | 设计约束 |
|---|---|---|
| 通用属性强化 | 当下变强、操作更舒服 | 尽量少而明确，避免大量同义数值 |
| 技能参数强化 | 强化某个技能的优势 | 必须影响实际执行，不能只改面板 |
| 技能形态变化 | 改变攻击、采矿或控制方式 | 必须说明与其他形态如何组合 |
| 技能觉醒 | 完成一个构筑目标 | 必须有明确条件、反馈和能力变化 |

不过，**“数值→专精→变形→觉醒”适合作为体验节奏，不适合作为所有角色必须走完的固定四级流程。**

否则会出现两种问题：

第一，前半局始终只能选择小幅数值，真正有趣的变化被拖到最后。第二，每条路线都要求固定前置，随机选择退化成“等我要的下一张牌”。

建议：

- 基础形态变化允许较早出现。
- 普通数值作为稳定补强与候选不足时的保底。
- 觉醒要求形成方向，但尽量避免必须按顺序抽齐多张指定牌。
- 可以采用“满足某类强化数量＋一个关键机制”的条件，而非固定五件套。

**还应区分两个概念：**

- **局内强化**：玩家选中的构筑内容，通常持续整局。
- **状态效果**：黄金爆头触发的三秒射速提升、中毒、减速等临时效果。

玩家可以统称它们为 Buff，程序和配置不能混为一类。前者涉及奖励、抽取、等级和前置；后者涉及目标、持续时间、叠层和移除。

## 3．通用属性与技能属性，需要避免重复付费

例如：

- 攻击伤害 +20%；
- Gunner 子弹伤害 +20%；
- Gunner 普攻伤害 +20%。

如果当前 Gunner 只有一种主要输出，这三种强化对玩家几乎是同一个选项。

建议每张强化至少满足一项：

- 覆盖范围不同，且玩家能理解；
- 强度与覆盖范围形成取舍；
- 改变资源消耗或使用方式；
- 与某个机制产生独特联动。

例如“全军伤害 +10%”与“Gunner 普攻伤害 +25%”可以共存，因为涉及军团收益与专精收益的选择。

“采矿效率 +40%”也必须拆清楚含义：是矿物伤害、动作频率、产出数量，还是整条生产线吞吐？这些会形成完全不同的玩法，不能用同一个词模糊处理。

## 4．天赋树：内容解锁成立，但不能让解锁成为惩罚

你希望天赋扩大玩法可能性，这个方向成立。不过“永久数值完全没有意义”过于绝对。

少量永久数值可以缓和新手挫败，但不应成为挑战高难度的主要门槛。核心仍应是新路线、新单位、新召唤师和新的操作选择。

最需要处理的是 **卡池稀释**：

> 解锁更多 Buff 后，原有构筑更难成型，玩家反而不愿意解锁。

建议采用：

- 永久解锁决定“可以使用什么”。
- 开局选择有限数量的构筑主题，决定本局主要候选范围。
- 通用池持续存在，保留一定跨主题发现。
- 本局已经形成的路线获得适度支持，但不保证每次都抽到目标牌。

不建议第一阶段再增加一整套永久“抽卡概率天赋”。它会与开局主题选择、召唤师倾向叠加，变成玩家难以判断的概率系统。

如果保留权重天赋，文案必须区分：

- 权重提高 20%；
- 出现概率增加 20 个百分点。

两者不是一回事。

## 5．召唤师：建议作为完整的开局规则包

召唤师适合本项目，因为它可以调整“自己操作”和“自动生产”的相对价值。

但召唤师解锁后，应该立即具备完整身份。不要出现：

> 花资源解锁 AI 指挥官，再花资源解锁自动作战，再花资源解锁其核心加成。

这会让玩家先拿到一个残缺角色。

额外天赋更适合解锁：

- 可替换的专长；
- 另一种主动能力；
- 不同的优势与代价组合。

同一召唤师的核心优势和代价应该同时生效。不能让后续天赋把代价逐步消掉，否则最终只是选择数值最高的召唤师。

对三个例子的判断：

| 例子 | 判断 | 主要问题 |
|---|---|---|
| 人口 +5、全单位属性 -10% | 可用，但应验证总生产与战斗收益 | 增加单位数量通常还增加并行工作能力，未必能靠 -10% 抵消 |
| 幻化性能 +100%、AI 性能 -50% | 方向鲜明，倍率需要收敛 | “性能”没有定义；可能把生产单位一起削到不可用 |
| AI 性能 ×2、禁止幻化 | 建议后置 | 当前手动采矿和幻化是主要交互，禁用后可能缺少足够的指挥玩法 |

尤其第三种，需要先有目标分配、优先级、集结或主动指令等交互。否则不是一种新的玩法，只是减少玩家可以做的事。

## 6．合体：必须有收益、代价和继承规则

合体最有价值的地方，是把单位数量、生产布局和战斗能力联系起来。

但草案中的：

> 5 个 OreBuddy → 1 个 Super OreBuddy，速度、容量、攻击、效率均 ×3。

不能直接判断为升级。

五台单位可以并行处理五个目标，一台三倍效率单位可能降低总吞吐；速度、容量又会影响运输周期，因此也不能简单用“3 小于 5”判断亏损。

应该至少比较：

- 单目标处理速度；
- 多目标并行能力；
- 搬运和寻路成本；
- 人口占用；
- 被摧毁后的损失集中程度；
- 飞行等新能力实际解决的问题。

建议高级单位拥有明确专长，而不是全部指标同步增加。例如：穿越复杂地形、处理高硬度矿物、压缩人口、提供区域增益。

**合体前必须确定以下规则：**

| 问题 | 建议的首版规则 |
|---|---|
| 什么时候发生？ | 玩家主动发起，不自动吞掉单位 |
| 哪些单位参与？ | 显式选中的、同阵营、可用单位 |
| 工作和货物怎么办？ | 先收尾任务、卸货，完成后才能合体 |
| 血量如何继承？ | 按配方规则转换，不能默认合体回满 |
| 强化怎么继承？ | 阵营/单位系列强化重新匹配一次；不把三份最终属性相加 |
| 高级单位算几个口？ | 配方明确配置 |
| 能否拆回？ | 第一阶段不支持，减少循环套利 |
| 合体算不算死亡？ | 不算战斗死亡，不触发击杀奖励和死亡扩散 |

## 7．合体与幻化的关系，是当前最大的待定产品规则

当前幻化是生成玩家身体，不接管场上的 AI 单位。

因此，“三个 Gunner 合成兰斯洛特”至少有两种不同设计：

| 方案 | 结果 | 成本 |
|---|---|---|
| 保持现有幻化模式 | 合体得到 AI 兰斯洛特，并可按规则开放玩家形态 | 要平衡 AI 单位与玩家形态同时存在的收益 |
| 改成接管真实单位 | 玩家控制场上合成出来的兰斯洛特 | 需要重做控制权、AI 恢复、单位身份、死亡和离体规则 |

**本评审建议首版保持现有幻化模式。** 合体是否额外开放玩家形态，作为配方的明确奖励；如果开放，文案应说明这是两个收益，不能隐含赠送。

“所有 Buff 对谁生效”也应明确。建议首版以“本方阵营”和“单位系列”为主，少做需要逐台管理的永久单体强化。这样新生产单位能继承构筑，合体也不必搬运大量个体养成数据。

## 8．高难度与重复游玩的理由，还需要补一层挑战设计

天赋树只能提供尚未解锁内容时的动力。解锁完成后，仍要靠局内变化和挑战本身支撑重玩。

高难度建议主要增加：

- 需要应对的新敌人行为或矿区事件；
- 更紧张的生产与战斗资源分配；
- 有明确取舍的任务条件；
- 不同路线的通关目标。

不建议主要依赖敌人血量倍增，再要求玩家刷永久攻击。

奖励可以采用首次突破奖励、稳定的难度收益提升，以及特殊挑战成就。基础内容应当在较低难度也能逐步解锁，避免形成“必须有高难度奖励，才能打过高难度”的循环。

**现有循环需要明确调整：**

目前 Boss 失败后回到生产阶段，单位和强化保留。若继续保持这一规则，建议把它定义为经营挑战模式。

Roguelite 模式则需要明确：

- 一局何时开始和结束；
- 失败保留哪些局外奖励；
- 局内资源和强化何时清空；
- 哪些阶段产生强化选择；
- 是否限制无风险无限生产。

不一定必须加全局倒计时。可以用有限矿区、阶段推进、订单目标或逐步增强的威胁建立边界。

## 9．建议的第一阶段内容范围

先做一个小而完整的验证版本：

| 内容 | 建议规模 |
|---|---|
| 召唤师 | 默认指挥官＋一个有明显取舍的变体 |
| 构筑主题 | 一条 Gunner 战斗路线、一条 OreBuddy 生产路线 |
| 局内强化 | 约 8～12 个，包含通用、技能参数、形态与觉醒 |
| 合体 | 一个配方 |
| 天赋 | 少量内容解锁节点，暂不做复杂权重树 |
| 奖励节奏 | 固定阶段奖励，先验证构筑，再引入更多随机来源 |
| 挑战 | 能实际体现范围输出、生产效率或资源取舍的目标 |

当前 Demo 最终目标是超级铁矿。单一高血量目标适合验证伤害，却不足以验证穿透、分裂、连锁传播的价值。要评估这些能力，需要相应的多目标场景。

功能验收应该观察：

- 玩家是否需要根据局势改变选择；
- 两条路线是否改变操作或资源分配；
- 合体是否有值得考虑的时机；
- 解锁新内容后是否更愿意尝试；
- 没抽到关键牌时是否仍有可玩的替代路线。
